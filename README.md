# Minton Video Library V1.3.2 — 배드민턴 유튜브 영상 라이브러리

**V1.3.1 수정(유지):** 다운로드 429 실패 행별 '↻ 다시받기' 버튼, **해당 항목만 재시도**, 자막 제외 MP4 재시도 모드, 실패 원인 표시, **로그 파일 열기** 버튼을 추가했습니다. 자세한 사용법은 아래 V1.3.1 단락을 확인하세요.

> 기존 사용자라면 [INSTALL.md의 V1.2 → V1.3 업데이트](INSTALL.md#3-v12에서-v13으로-업데이트)를 먼저 확인하세요. Windows GUI 및 실제 YouTube 다운로드까지 완료한 통합 검증은 아직 수행하지 않았습니다. yt-dlp는 YouTube의 변경 사항과 영상 접근 권한에 영향을 받습니다.

## V1.3.2: 유튜브 영상 주소 및 라이브러리 저장 공간

### 동영상 목록의 유튜브 주소

- 라이브러리의 `재생시간` 다음에 **유튜브 주소** 열이 추가됩니다. 제목·채널·재생목록·메모·분류 등 기존 열은 모두 유지됩니다.
- 주소 셀을 **한 번 클릭**하면 Windows의 기본 웹브라우저에서 해당 **개별 영상**을 엽니다. 다른 열을 더블클릭하면 기존처럼 내장 플레이어로 재생합니다.
- DB `videos.source_url`에 주소가 없는 기존 영상도 영상 ID가 YouTube 형식(11자리)이면 `https://www.youtube.com/watch?v=영상ID`로 링크가 자동 표시됩니다.
- 완전히 로컬에서 만든 영상처럼 YouTube ID가 없다면 **주소 없음**을 표시합니다. 존재하지 않는 유튜브 주소는 만들지 않습니다.
- 링크 텍스트를 직접 볼 수 있고, 주소 열도 다른 열과 동일하게 너비를 마우스로 조절할 수 있습니다. 이전 V1.3.1의 11개 열 너비 설정은 **유튜브 주소 1개 열만 삽입**해 이전됩니다.
- 검색창에서는 `videos.source_url` 원본 주소도 검색할 수 있습니다. YouTube ID 검색도 유지됩니다.

### 저장 드라이브 공간과 전체 영상 크기

- 맨 위 저장 폴더 아래의 **저장 드라이브** 줄에는 해당 드라이브의 **남은 공간 / 전체 공간**, **디스크 사용률 바**를 표시합니다. 별도 드라이브의 공간을 보여주지 않습니다.
- 같은 줄의 **전체 동영상**에는 `등록된 실제 영상 파일 개수 / 합계 크기`를 표시합니다.
- 전체 영상 합계는 현재 검색어, 채널, 대분류 필터와 **무관한 전체 라이브러리** 기준입니다. 다른 폴더에 누락되어 있거나 삭제된 영상은 합계에서 제외합니다. 동일한 미디어 경로가 DB에 중복 등록된 경우 한 번만 셉니다.
- 용량 계산은 **MP4·MKV·MOV·WebM 등 영상 파일만** 포함합니다. SRT/JPG/JSON/SQLite는 제외합니다. 동영상과 관련된 부가 파일을 포함한 전체 폴더 크기와는 다를 수 있습니다.
- 앱 실행, 다운로드 완료, 폴더 검색 완료, 저장 루트 변경 및 파일 이동·휴지통 삭제 시 갱신합니다. 추가로 **60초마다 자동 갱신**합니다.
- 폴더에 영상을 직접 추가했다면 **폴더 다시 검색**을 눌러 등록해야 영상 합계에 반영됩니다. 기존 자동 스캔도 계속 동작합니다.
- 라이브러리를 다른 드라이브로 옮겨도 상대경로 DB 사용 방식은 동일합니다.

### V1.3.1에서 업데이트

1. 현재 실행 중인 앱을 종료합니다. 다운로드·썸네일 수집 중이라면 중단 후 종료합니다.
2. 중요한 메모가 있다면 `라이브러리루트\_database\library.db`를 **프로그램 종료 상태에서 백업**합니다.
3. 새 ZIP의 `minton_video_library.py`, `README.md`, `INSTALL.md`, `.gitignore`를 기존 프로젝트 폴더에 덮어씁니다. 동영상, DB, 자막, 썸네일은 그대로 둡니다.
4. ` .\.venv\Scripts\python.exe minton_video_library.py`로 실행한 후 **폴더 다시 검색** 버튼을 누릅니다.

**V1.3.2는 DB 스키마에 새로운 컬럼을 추가하지 않습니다.** 이전 메모·분류·작업·클립 기록은 그대로 보존합니다.

## V1.3.1: 다운로드 실패 복구 / 로그 파일 직접 열기

### 실패한 개별 동영상만 다시받기

1. 상단 **다운로드 진행** 표에서 상태가 **실패**인 행을 찾습니다.
2. 해당 행 가장 오른쪽의 **↻ 다시받기** 버튼을 누릅니다. 오른쪽 열이 보이지 않으면 표를 좌우로 스크롤하거나 창 폭/열 너비를 조절합니다.
3. 실패 원인에 따라 아래 두 가지 중 하나를 선택합니다.
   - **영상+자막 다시받기**: 기존 사용자 설정대로 영상, 한국어 일반/자동 자막, JPG 썸네일, `.info.json` 다운로드를 재시도합니다.
   - **자막 제외하고 영상만**: 한국어 자동번역 자막(`ko-vi`)에서 `HTTP 429`가 발생할 때 추천. 자막 다운로드만 생략하고 기존의 MP4·JPG 썸네일·메타데이터 다운로드를 수행합니다. **기존에 저장된 SRT를 삭제하지 않습니다.**
4. 선택한 **해당 작업 1건만** 시작됩니다. 다른 대기열 작업은 실행되지 않으며 기존 `--continue` 이어받기 동작도 유지합니다.
5. 오류 메시지는 화면의 **오류/메시지** 열과 하단 로그에 기록됩니다. 기존 버전에서 남은 작업의 짧은 `yt-dlp 종료 코드 1` 메시지는 원본 로그 파일로 원인을 확인합니다.

**중요:** `HTTP 429: Too Many Requests`는 YouTube 서버가 요청을 제한했다는 뜻입니다. 자막을 제외하면 자막 엔드포인트 요청은 피할 수 있지만 영상/메타데이터 요청 자체도 제한된 경우에는 여전히 실패할 수 있습니다. 반복적으로 클릭하지 말고 충분한 간격을 두고 다시 시도하세요. 저작권과 서비스 이용약관을 준수하는 콘텐츠만 다운로드하세요.

### 상세 로그 바로 열기

다운로드 시작/재개 버튼 근처의 **로그 파일 열기** 버튼을 누르면 Windows 메모장으로 기존 파일을 엽니다.

```text
%LOCALAPPDATA%\MintonVideoLibrary\logs\minton_video_library.log
```

로그를 삭제하거나 다른 경로로 옮기지 않습니다. 메모, 영상 파일, 분류, DB는 기존과 동일하게 `minton.youtube\_database\library.db` 및 채널 폴더에 유지됩니다.

### 이미 있던 '선택 항목 다시 대기'와의 차이

- **실패 행의 ↻ 다시받기**: 그 항목 하나만 즉시 재시도할 수 있고, 자막 제외 옵션을 선택할 수 있습니다.
- **선택 항목 다시 대기**: 예전과 동일하게 선택한 항목(여러 개 가능)을 대기 상태로 되돌립니다. 이후 전체 다운로드 시작/재개 버튼을 누르면 대기열을 순서대로 처리합니다.

## V1.3: 썸네일 및 오디오 사용법

1. **신규 다운로드**: MP4, 한국어 자막, `.info.json`과 함께 JPG 썸네일을 저장합니다. YouTube가 썸네일을 제공하지 않거나 접근 실패 시 영상은 그대로 두고 누락 로그를 남깁니다.
2. **기존 영상의 누락 이미지**: 다운로드가 실행 중이지 않을 때 라이브러리 상단 **누락 썸네일 받기**를 클릭합니다. 이미지가 없는 영상 중 YouTube ID/원본 URL을 알 수 있는 항목을 한 개씩 요청하며 기본 3초 간격을 둡니다. `--skip-download`이므로 MP4는 재다운로드하지 않습니다. **썸네일 중단** 후 재실행하면 성공한 항목은 건너뜁니다.
3. **썸네일 표시**: 라이브러리 맨 앞 열에 표시하며, 영상을 선택하면 상세 패널에도 크게 나옵니다. 화면에 보이는 행만 이미지를 불러와 영상이 많아도 무리하지 않도록 했습니다. JPG/PNG/WEBP 파일을 찾아 보여줍니다.
4. **재생 버튼**: 재생 중 `Ⅱ 일시정지`, 멈춘 상태 `▶ 재생`으로 바뀌는 통합 버튼입니다. `■ 정지`는 별도 유지합니다.
5. **소리**: 출력 장치 콤보에서 Windows 스피커/헤드셋을 직접 선택할 수 있습니다. `🔊` 버튼은 음소거 토글입니다. `소리 진단` 버튼은 Qt 감지 오디오 트랙, 출력 장치, 음량/음소거 및 FFprobe 코덱을 비교해 보여줍니다. Windows 볼륨 믹서에서 Python 실행 프로그램의 음소거 상태도 확인하세요.
6. **재생목록명·재생시간**: 기존 `채널/재생목록/영상` 폴더와 `.info.json`에서 목록명을 복구합니다. 재생시간 메타데이터가 없으면 백그라운드 폴더 검색에서 `ffprobe`로 길이를 채웁니다. 로컬 파일에 재생목록 정보가 없으면 빈칸입니다.

> 영상에 오디오 트랙이 없거나 Qt/Windows가 선택한 출력 장치에 접근할 수 없다면 코드만으로 소리 출력을 보장할 수 없습니다. 진단 결과가 필요한 원인 확인 수단입니다. 인터넷 연결, yt-dlp 접근 권한, 지역 제한 등에 따라 썸네일 수집이 실패할 수 있으며 그 경우 영상·메모는 변경하지 않습니다.

### 향후 개발 제안

1. **V1.4: 실제 구간 커팅** — 시작/종료 기록을 FFmpeg MP4로 출력하고 SRT 시간 보정, JPG 대표 이미지를 함께 내보내기.
2. **V1.5: 휴대폰용 내보내기** — H.264/AAC 호환 MP4, 크기·해상도·용량 선택, 파일명과 폴더 구조 정리.
3. **V1.6: 클립 데이터셋 고도화** — 스매시/수비/복식 전후위 등 다중 태그, 즐겨찾기·중요도·AI 자세분석 프로그램에 클립 전달.

예시 영상 제목과 날짜는 설명용입니다. `PLX1IndZwkjj0` 재생목록에 관해서는 사용자가 확인한 `윤이콕TV\물A조라고 놀리지말아요` 폴더명을 적용합니다. 기타 제목은 YouTube가 제공한 한국어 데이터를 우선하며 **영어 제목을 자동 번역하지는 않습니다.**

### 저장 방식과 디스크 이동

`library.db`의 `videos.file_path`에는 `윤이콕TV/물A조라고 놀리지말아요/영상.mp4`처럼 **라이브러리 루트 기준 상대경로**만 저장합니다. 따라서 `minton.youtube` 폴더 전체를 `E:` 또는 외장 하드로 옮겨도 DB와 영상 간 관계가 유지됩니다. 다만 새 디스크의 폴더 위치는 프로그램에 한 번 알려줘야 합니다.

1. **프로그램을 완전히 종료**합니다. 영상·자막·`_database`를 포함한 **`minton.youtube` 폴더 전체**를 새로운 드라이브로 복사합니다.
2. 새 드라이브에서 영상과 `_database/library.db`가 모두 복사되었는지 확인합니다.
3. 프로그램 재실행 → 이전 폴더가 없으면 **새 라이브러리 폴더 선택** 창이 열립니다. 이전 폴더가 남아 있으면 상단 **찾기**로 새 폴더를 선택하세요. **DB 폴더** 버튼으로 실제 DB 위치를 열 수 있습니다.
4. 새 폴더는 `_database` 폴더가 포함된 `minton.youtube`의 **최상위 폴더**를 선택합니다. DB가 없는 폴더라면 기존 DB 복사/새 라이브러리 시작을 확인하는 메시지가 나옵니다.
5. **폴더 다시 검색** 후 제목·채널·메모·분류·구간 기록·동영상 크기를 확인합니다. 원본 드라이브의 파일은 검증 뒤에만 정리하세요.

다른 PC에서 실행할 때는 다음처럼 시작 폴더를 지정할 수도 있습니다.

```powershell
.\.venv\Scripts\python.exe .\minton_video_library.py --root "E:\minton.youtube"
```

`%LOCALAPPDATA%\MintonVideoLibrary\library_location.json`은 **마지막 사용 라이브러리 경로 힌트**만 담습니다. 이 파일과 기존 로테이션 로그는 옮기지 않아도 됩니다. **메모/분류/태그/구간/대기열/설정의 본 데이터는 영상 폴더 안의 SQLite에 있습니다.**

> SQLite 사용 중 `_database\library.db-wal` 또는 `library.db-shm` 파일이 생길 수 있습니다. 라이브러리 디렉터리는 **앱을 완전히 종료한 후** 옮겨야 하며, V1.2 종료 시 WAL 체크포인트를 시도합니다. 안전을 위해 정기적으로 `_database`를 백업하세요.

## 권장 배드민턴 분류 체계

현재 버전은 **사용자가 직접 분류를 선택하는 방식**입니다. 자동 AI 기술 판정은 없습니다. 대분류 하나와 세부분류 하나를 선택하며 중복 특성은 태그를 여러 개 입력합니다.

| 대분류 | 세부분류 예시 |
|---|---|
| 미분류 | 미분류 (신규 영상의 기본값) |
| 기초·기본기 | 그립, 준비 자세·스플릿 스텝, 풋워크, 타점·스윙, 체중이동 |
| 스트로크·기술 | 클리어, 스매시, 드롭·컷트, 헤어핀, 드라이브, 푸시, 리프트, 백핸드, 서브, 리시브 |
| 수비·리턴 | 스매시 수비, 드라이브 수비, 네트 수비, 서브 리턴, 수비→공격 전환 |
| 전술·포지션 | 단식, 복식 전위·후위·로테이션, 혼합복식, 경기 전술, 상대 대응 |
| 레슨·코칭 | 입문·중급·상급 레슨, 개인 레슨, 자세 분석·교정, 드릴, 코치 시범 |
| 대회·경기 영상 | 국제·국내·동호인 대회, 단식·복식·혼합복식, 하이라이트, 경기 분석 |
| 운동·장비·기타 | 근력, 유연성·부상 예방, 라켓·스트링, 규칙·판정, 기타 |

**분류 사례:** 복식 스매시 수비 영상은 `대분류=수비·리턴`, `세부분류=스매시 수비`, `태그=복식, 후위, 리시브, 레슨`으로 저장합니다. 다운로드 영상은 스캔·중복 확인으로 갱신해도 분류·메모를 덮어쓰지 않습니다.

## 클립 구간 기록 (휴대폰 시청을 위한 준비)

1. 영상을 선택해 필요한 동작이 나오는 지점에서 일시정지하고 **클립 구간 기록** 탭의 `현재 시각 → 시작점`을 누릅니다.
2. 끝 위치로 이동하여 `현재 시각 → 종료점`을 누릅니다.
3. `구간명`을 입력하고 **구간 후보 저장**을 누르면 SQLite `clip_marks` 테이블에 시작·종료 밀리초와 이름이 저장됩니다.
4. 기록을 더블클릭하거나 **구간 시작 재생**으로 해당 시점에 이동합니다. 잘못된 기록은 **선택 구간 삭제**로 제거합니다.

V1.2는 **원본 MP4를 자르거나 휴대폰용 클립 파일을 출력하지 않습니다.** 후속 버전에서는 FFmpeg로 선택된 구간을 H.264/AAC MP4로 내보내고, 필요 시 SRT도 동반 자르도록 확장할 수 있습니다. 원본 MP4는 이미 최대 1080p H.264/AAC를 우선 다운로드하므로 일반적인 Android 재생 호환성에 유리하지만, 기기별 코덱 지원·파일 크기 제한은 별도 확인이 필요합니다.

## 기존 기능 사용 요약

- 주소를 한 줄씩 입력하고 **대기열에 추가** → **다운로드 시작**. 재생목록은 먼저 확장된 후 각 영상이 차례로 내려받아집니다.
- 필요하면 채널/재생목록 이름을 직접 지정합니다. 재생목록에 같은 영상이 다시 포함된 경우 기존 파일을 우선 사용합니다.
- 하단 **영상 라이브러리**에서 검색/채널·분류 필터, 컬럼 폭 조절, 파일 크기 확인이 가능합니다.
- 선택 영상의 우측 **영상 메모**, **배드민턴 분류·태그**, **클립 구간 기록**, **전체 자막 / 구간 이동** 탭을 사용합니다.
- **파일 이동**, **한글 제목/파일명 변경**, **영상 휴지통 삭제** 기능은 V1.1 그대로 유지합니다. 탐색기에서 삭제한 영상은 기본 화면에서 숨기며 메모/분류 데이터는 보존합니다.
- 현재 영상의 자막은 영상 위에 합성되는 것이 아니라 플레이어 하단과 전체 자막 목록에 표시됩니다.

## yt-dlp 다운로드 핵심 옵션

```text
--js-runtimes deno --remote-components ejs:npm
--extractor-args "youtube:lang=ko"
-f "bv[vcodec^=avc1][height<=1080]+ba[acodec^=mp4a]/b[vcodec^=avc1][height<=1080]"
--merge-output-format mp4
--write-subs --write-auto-subs --sub-langs "ko.*" --convert-subs srt
--write-info-json --no-playlist --continue
```

여기에 URL별 폴더 출력 템플릿, 프래그먼트 재시도, 로그/진행률 확인, `after_move:filepath` 저장 결과 확인 등이 추가됩니다. 영상이 H.264/AAC 스트림을 제공하지 않는 경우 형식 조건 때문에 실패할 수 있으며 자동으로 AV1/WebM으로 변경하지 않습니다.
